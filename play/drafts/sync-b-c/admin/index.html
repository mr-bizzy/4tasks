4Tasks: information for IT administrators

For the person who manages a Microsoft 365 or Google Workspace organisation whose user asked to connect 4Tasks.

What 4Tasks is

4Tasks is a private to-do and reminder app for Android. A person's lists and tasks are kept on their phone. If they choose, 4Tasks syncs those tasks with Microsoft To Do or Google Tasks, so they can use the same tasks on other devices. 4Tasks has no server of its own: it talks only to Microsoft or Google, never to the publisher, and the publisher receives nothing. There is no advertising, analytics or crash reporting. See the privacy policy and the home page.

It cannot read mail, files, calendars, contacts or other people's data, and it asks for no application (background, organisation-wide) permission. It can create, change and delete that person's tasks, because syncing means making the same changes on both sides.

Microsoft 365 (Microsoft Entra ID)

What it asks for

Delegated Microsoft Graph permissions, on behalf of the signed-in user only:

  • Tasks.ReadWrite: create, read, update and delete the signed-in user's tasks and task lists. This is the one that matters. Microsoft's permissions reference lists it as not requiring admin consent by default.
  • User.Read, openid, email: the user's name and email address, shown as the account's name in the app.
  • offline_access: so the app can keep syncing without asking the user to sign in each time.

If your users see "Need admin approval" or cannot consent

Whether a user can accept the consent screen is set by your organisation's user consent settings. Two ways to allow 4Tasks:

  1. Grant admin consent for the organisation (users then see no prompt). Sign in to the Microsoft Entra admin center as at least a Cloud Application Administrator, then Entra ID > Enterprise apps > All applications, search for 4Tasks, select it, choose Permissions under Security, review the permissions above and select Grant admin consent. If 4Tasks is not listed yet, an administrator can use this link, which asks for the same consent:
    https://login.microsoftonline.com/organizations/adminconsent?client_id=[MICROSOFT_CLIENT_ID]
  2. Let users request approval. A Global Administrator turns on the admin consent workflow: Entra ID > Enterprise apps > Consent and permissions > Admin consent settings, then under Admin consent requests set Users can request admin consent to apps they are unable to consent to to Yes and choose reviewers. The user then sees a request option in the app's sign-in; reviewers approve it and the user is told.

Granting consent for everyone lets all users sign in to the app unless you require user assignment for it. Sign-in can also be refused by conditional access or tenant restrictions, which only you can change. Source: Microsoft's pages on granting tenant-wide admin consent and the admin consent workflow.

Google Workspace

What it asks for

One scope, on behalf of the signed-in user: https://www.googleapis.com/auth/tasks (“Create, edit, organize, and delete all your tasks”). The user picks a Google account that is already on the phone; Android's account manager gives 4Tasks a short-lived access token for that scope only. 4Tasks does not ask for sign-in to other Google services, and requests no Drive, Gmail, Calendar or contacts access.

If your users are told access is blocked

In the Admin console:

  1. Go to Menu > Security > Access and data control > API controls.
  2. Choose Manage App Access, then Configure new app.
  3. Search for 4Tasks, or for its client ID above, and choose it. (To add several apps at once you can upload a CSV with type Android and the package name uk.mr_biz.fourtasks; Google's bulk page says an Android app may be entered by OAuth client ID or by package ID.)
  4. Choose who it applies to (the whole organisation or an organisational unit) and set access to Limited or Specific Google data (then add the Tasks scope above).
  5. Save. Changes can take a while to apply.

Google's four settings are Trusted (all Google services), Limited (only unrestricted services), Specific Google data (only the scopes you list) and Blocked. Tasks is not one of Google's restricted scopes, so Limited should be enough; Blocked, or an organisation-wide rule that blocks apps you have not configured, stops 4Tasks, and a blocked user sees your message or Google's default. Sources: Google's pages on controlling which apps access Google Workspace data and adding and configuring third-party apps in bulk. Removing 4Tasks again

A user removes the account in 4Tasks (Settings, Accounts, the account, Log out), which deletes that account's copy on the phone. Access can also be revoked from the provider's side: in Microsoft Entra, delete the enterprise application or remove its consent; in Google, remove the app from the user's account permissions or block it in the Admin console. Tasks already synced stay in the user's Microsoft or Google account until deleted there.
